# Telegram /profit: понятный отчёт о результате бота

Статус: согласовано пользователем 2026-10-03.

## Задача и выбранный вариант

Добавить команду `/profit`, которая объясняет денежный результат собственных сделок бота. Альтернативный вариант — расширить существующую `/stats`. Отдельная команда подходит запросу пользователя на новый понятный отчёт, а `/stats` остаётся доступной для статистики.

## Содержание сообщения

1. Название отчёта и текущий режим. В DEMO явно указать виртуальные средства.
2. За всё время по журналу текущего режима: заработано на прибыльных завершённых сделках, потеряно на убыточных завершённых сделках, комиссии этих сделок, чистый итог и количество прибыльных/убыточных/нулевых сделок.
3. Сегодня по UTC: чистый итог завершённых сделок и их количество. Граница дня соответствует существующим `/status` и дневному контролю риска; зона подписана явно.
4. Открытые позиции: количество и текущий результат по цене возможного закрытия (bid для Long, ask для Short), с учётом уже исполненных частичных закрытий и уже списанных комиссий.
5. Общий текущий результат: итог завершённых сделок плюс результат ещё открытых позиций. Отдельно пояснить, что результат открытых позиций меняется и будущая комиссия закрытия в оценку не входит.
6. Когда `TRADING_CAPITAL_USDT` задан: исходный выделенный капитал, расчётный капитал с результатом собственных сделок и изменение в процентах относительно исходного капитала. Это расчёт, а не отдельный биржевой кошелёк. Без заданного капитала не выводить процент от полного баланса аккаунта.

Денежные значения показывать с максимум шестью знаками после запятой, положительные итоги — со знаком `+`, потери — со знаком `−`. Суммы выигрышей и потерь уже включают комиссии; строка комиссий справочная, повторно их не вычитать.

## Расчёт и достоверность

- Фильтровать все записи по текущему режиму, чтобы PAPER/DEMO/LIVE не смешивались.
- Для завершённых сделок суммировать `Trade.netPnL`: положительные и отрицательные значения отдельно. Их сумма — чистый итог.
- Комиссии завершённых сделок — сумма `Trade.fees`.
- День завершения определять по `Trade.exitTime`; сохранённый timestamp строки trades равен exitTime.
- Итоги за всё время агрегировать в SQLite без ограничения количества последних сделок и без загрузки всей истории в память сервера.
- Открытый результат каждой позиции равен `grossPnL - fees + (mark - entry) * quantity * direction`, где direction равен 1 для Long и −1 для Short. Частичные закрытия уже входят в grossPnL и fees позиции.
- Если свежая котировка отсутствует, текущую денежную оценку открытых позиций и общий текущий итог обозначить как недоступные. Завершённые сделки остаются достоверными; не заменять отсутствующую котировку ценой входа и не показывать ложный ноль.
- При несинхронизированном состоянии аккаунта или отключённом приватном потоке оценку текущего общего результата также обозначить как недоступную до сверки позиций.
- Итоги нулевой истории равны нулю. При отсутствии позиций открытый результат равен нулю.
- Расчётный капитал равен заданному начальному капиталу плюс чистый результат завершённых сделок плюс доступная оценка открытых позиций. Не подменять его лимитом для новых ордеров из `/status`, который может ограничивать отображаемый капитал.

## Интеграция и проверка

Команду добавить в разрешённый перечень Telegram. Использовать существующую проверку chat ID и форматирование сообщений. Обработчик только читает журнал и текущие котировки, не изменяет паузу, защитные состояния, стратегию или торговые настройки.

Тот же отчёт доступен для проверки как JSON через read-only `GET /api/profit` на существующем loopback HTTP API. Это позволяет проверить работающий экземпляр и форматтер без отправки тестового сообщения в Telegram.

Проверить расчёты на смешанной истории с прибылью, убытком и нулевым итогом, границу UTC-дня, разделение режимов, отсутствие двойного вычета комиссий, Long/Short и частичное закрытие, устаревшие котировки и доступ только разрешённому чату. Затем выполнить typecheck, lint, тесты и build.

После проверки опубликовать изменение в существующем репозитории и обновить работающую службу `trad-baybit` на сервере. Сборку выполнить локально. При обновлении сохранить серверную SQLite и `/etc/trad-baybit/demo.env`; локальным старым снимком базу не заменять. Проверить команду через обработчик на сервере, готовность Bybit и доступность оставшихся сайтов.
